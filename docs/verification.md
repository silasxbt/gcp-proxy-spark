# 验证记录

首版开发日期：2026-10-20。所有测试使用合成凭证和测试 IP，未修改现有生产 VM。

## 验证层级

- 单元/HTTP 测试：结构化输出、兼容约束、隐藏节点、URI 编码、令牌保护、HEAD、未就绪状态、流量重启/重置/跨月、私有文件权限、失败回退。
- 原生验证：sing-box 1.13.19 服务端与客户端、Mihomo 1.19.32 客户端；包含显式启用的 VMess WS。
- 实际连接：本机生成临时证书，仅在测试进程信任/固定该证书；两个核心各通过五种协议访问本机 HTTP 服务。不会关闭 TLS 校验；没有公网地区可用性结论。
- Linux CI：amd64/arm64 原生实连、network namespace 内真实 IPv4/IPv6 nftables 字节增量、计数表重建。
- 生命周期 CI：临时 GitHub runner 上真实 systemd/Nginx 安装、升级、回退、故障恢复、续期 hook、保留数据卸载。CA 签发由测试替身完成，不是公开 ACME 验证。

本地结果和 CI 最终状态在发布前更新；自动化工作流见 `.github/workflows/ci.yml`。失败的检查不能用说明文档替代。

## 未验证 / 必须现场验收

1. 公网 IP 的 Let's Encrypt 实际签发、自动续期与外部到期监控：需要已授权的测试公网主机，不在现有生产机器演练。
2. Shadowrocket 真机导入与连接：仅 URI 输出测试，不具备 iOS 真机验收证据。
3. 中国大陆网络可达性与排序：标签为经验建议，无分地区实测保证。
4. 实际 GCP 防火墙和外部 UDP 连通：本机/隔离 CI 不能替代目标网络验收。
5. 停电丢失采样增量、长停机跨月估算是已说明的统计限制，不可用作账单计费。

生产部署前需按 deployment.md 完成以上适用项。不要把“配置校验通过”写成“所有客户端/所有网络可用”。
